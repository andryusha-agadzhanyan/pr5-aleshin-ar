## Назначение

Программа проверяет табель из пяти чисел через `;` и считает сумму, среднее,
число дней с часами больше 8 и показатели варианта 3.
В этом варианте `weeklyOvertime` считает **недоработку**: `max(0, 40 - total)`.
`addRestHours` по условию имеет ту же формулу и вызывает `weeklyOvertime`.
Для 30 часов оба метода возвращают 10; для 50 часов оба возвращают 0.
Исходное имя `weeklyOvertime` сохранено согласно методичке.

## Сборка

Нужен JDK 17 или новее; проверено компилятором OpenJDK 17.0.20.
Внешних библиотек, Maven, Stream API и лямбда-выражений нет.
Команды выполняются в корне проекта, где находятся `src` и `data`.

Linux/macOS:

```bash
bash run_selfcheck.sh
```

Windows:

```bat
run_selfcheck.bat
```

Вручную на любой системе:

```text
mkdir out
javac -encoding UTF-8 -d out src/ru/edu/pr02/TimesheetAnalyzer.java src/ru/edu/pr02/SelfCheck.java
java -cp out ru.edu.pr02.SelfCheck
```

Если `out` уже существует, создавать его снова не нужно.
Если `javac` не найден, нужно установить JDK и добавить его `bin` в PATH.
Ожидаемые итоги:

```text
UNIT: 47 PASS, 0 FAIL
DATA: 18 PASS, 0 FAIL
TOTAL: 65 PASS, 0 FAIL
```

Сохранены все 19 случаев PDF с ожиданиями по варианту 3.
Добавлены 2 проверки части А, 2 части Б, 14 собственных и 10 проверок контрактов массивов.
Успешный запуск возвращает код 0, наличие FAIL — код 1, неверные аргументы — код 2.

## Интерактивный режим

После сборки:

```text
java -cp out ru.edu.pr02.SelfCheck --interactive
```

Или со сборкой: `bash run_selfcheck.sh --interactive` / `run_selfcheck.bat --interactive`.

```text
8;9;10;8;8
OK:sum=43,avg=8.60,od=2,wo=0,rh=0
6;6;6;6;6
OK:sum=30,avg=6.00,od=0,wo=10,rh=10
8;8;17;8;8
Ошибка: позиция 3 -- значение вне диапазона [0, 16]
```

`sum` — сумма, `avg` — среднее с двумя знаками, `od` — дни с переработкой,
`wo` — недоработка по части А, `rh` — часы отдыха по части Б.
Для выхода ввести `exit` или пустую строку. Конец входного потока также завершает режим.
После ошибочной строки можно сразу вводить следующую.

## Проверки из файла

По умолчанию после unit-проверок читается `data/sample.csv`.
Другой файл можно проверить без перекомпиляции:

```text
java -cp out ru.edu.pr02.SelfCheck --data data/my_cases.csv
```

Формат строки: `вход|ожидание|комментарий`. Пустой табель обозначается `EMPTY`.
Строки, начинающиеся с `#`, и пустые строки файла пропускаются.
В успешном ожидании нужны четыре показателя в порядке `sum,avg,od,wo`.
Для проверки части Б можно добавить необязательный показатель `rh` в конец.

```text
7;8;8;8;8|OK:sum=39,avg=7.80,od=0,wo=1|часть А
6;6;6;6;6|OK:sum=30,avg=6.00,od=0,wo=10,rh=10|часть Б
8;8;17;8;8|ERROR:позиция 3|ошибка диапазона
EMPTY|ERROR:структура|пустой табель
```

## Правила ввода

- Ровно пять целых от 0 до 16 включительно, без знака и ведущих нулей.
- `0` допустим; `08`, `+8`, `-3`, `8.5`, пробелы и пустые поля запрещены.
- `trim()` не применяется, `split(";", -1)` сохраняет пустые поля в конце.
- Сначала проверяется структура, затем значения слева направо до первой ошибки.
- Позиции считаются с 1; ошибки данных представлены IllegalArgumentException.
- Дроби и отрицательные — ошибки формата; 17 и слишком длинные целые — ошибки диапазона.
- Методы расчётов проверяют null и длину массива; диапазон проверяется в parseHours.
